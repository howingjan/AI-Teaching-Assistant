# ADR-005：失败优先的评测文化（保留失败案例 + 成本/延迟监控）

- **状态**：已采纳（Phase 4）
- **日期**：2026-08
- **背景**：产品规划第 7.3 节明确“不要只展示成功截图”，必须记录失败案例；面试/作品集更重要的是说明如何发现失败并修复。
- **决策**：
  1. 每次评测运行都自动把失败（管道异常、引用不准确、资料外未拒答、需人工确认的引用告警）写入 `data/output/failures/failures.json` + `failures.md`；
  2. 用 `UsageMonitor` 记录每次生成的延迟、tokens 与预估成本，追加到 `logs/usage.jsonl`，并聚合进评测报告；
  3. 评测指标独立复算（引用准确率、字段完整率、资料外拒答率、任务专项检查）。
- **理由**：
  1. 失败案例是改进的输入：每条记录包含现象、如何发现、根因与处理；
  2. 成本/延迟监控让“单次生成成本”“平均响应时间”成为可复现的工程指标（7.2）；
  3. 独立复算避免“自己校验自己”的乐观偏差。
- **关键记录**（截至 2026-08-30 的真实失败）：
  - 期末复习把结论引到第 59 页（超出文档范围）——已由引用校验拦截并提示老师；
  - 作业讲题引用页码第 18 页超出 Assignment 1 范围；
  - Phase 1 早期中文“缺失值”无法命中英文课件——已通过多语言 embedding 解决。
